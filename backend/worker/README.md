# Reelio AI — FFmpeg render worker

Исполнитель рендера из [контракта](../../docs/render-contract.md) v1. Читает
`plan.json` из хранилища, собирает вертикальный MP4 9:16 и кладёт его обратно,
отчитываясь о прогрессе через внутренний канал backend'а (§8.1).

Worker **не имеет доступа к Firestore** и не подписывает URL — по §9 его права
ограничены одним бакетом. Всё остальное делает backend.

```
plan.json ──► [ffprobe] ──► filter_complex ──► libx264/AAC ──► MP4 + обложка + SRT
                  │                                               │
                  └──────── POST /internal/jobs/{id}/progress ◄────┘
```

## Что он делает

| Этап | Содержание |
|---|---|
| Разбор | Повторная проверка инвариантов §2: клипы, материалы, пути, потолок 120 с |
| ffprobe | Пригодность каждого исходника, rotation metadata, наличие и громкость звука |
| Кадрирование | Масштаб с сохранением пропорций + кроп (или поля) до точного кадра 9:16 |
| Видео | Обрезка по таймкодам, pan/zoom для фото, переходы cut / fade / dissolve / slide / zoom |
| Субтитры | Кириллические SRT и ASS, стили `clean` / `bold` / `karaoke`, вшивание в кадр |
| Звук | Нормализация речи, музыкальная подложка, ducking через `sidechaincompress` |
| Кодирование | H.264 high / yuv420p / AAC 48 кГц стерео, `+faststart`, GOP = 2 × fps |
| Проверка | ffprobe готового ролика + проверка порядка боксов `moov`/`mdat` |
| Выгрузка | MP4, обложка 9:16, `captions.srt`, `logs/worker.log` |
| Уборка | Временные файлы удаляются всегда — и после успеха, и после ошибки, и после отмены |

## Запуск

Worker целиком настраивается переменными окружения (§9); аргументов командной
строки у него нет.

| Переменная | Обяз. | Значение |
|---|---|---|
| `REELIO_JOB_ID` | да | Идентификатор задачи |
| `REELIO_PROJECT_ID` | да | Идентификатор проекта; ограничивает пути (§6) |
| `REELIO_PLAN_URI` | да | `gs://…/plan.json` или `file://…/plan.json` (§10) |
| `REELIO_OUTPUT_PREFIX` | да | `projects/{projectId}/jobs/{jobId}/output` |
| `REELIO_PROGRESS_URL` | нет | Канал §8.1; без него worker работает автономно |
| `REELIO_WORKER_TOKEN` | нет | Bearer для канала §8.1 (Secret Manager) |
| `REELIO_BUCKET` | нет | Бакет; в cloud mode берётся из `REELIO_PLAN_URI` |
| `REELIO_CONTRACT_VERSION` | нет | По умолчанию `1` |

Дополнительные настройки образа:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `REELIO_FIT_MODE` | `cover` | `cover` (кроп), `contain` (поля §1), `blur` |
| `REELIO_X264_PRESET` | `medium` | Пресет libx264 |
| `REELIO_WORK_DIR` | `$TMPDIR/reelio-{jobId}` | Каталог временных файлов |
| `REELIO_MUSIC_DIR` | `/opt/reelio/music` | Каталог музыкальных треков |
| `REELIO_FONTS_DIR` | `/usr/share/fonts` | Каталог шрифтов для субтитров |
| `REELIO_FONT_NAME` | `DejaVu Sans` | Шрифт субтитров (нужна кириллица) |
| `REELIO_HEARTBEAT_SECONDS` | `15` | Период heartbeat (контракт требует ≤ 30 с) |
| `REELIO_KEEP_TMP` | `false` | Не удалять рабочий каталог (отладка) |
| `REELIO_LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |

Код выхода: `0` — успех или корректная отмена, `1` — сбой (backend уже получил
`phase: "failed"` с кодом §7).

### Локально

```bash
cd backend/worker
REELIO_JOB_ID=job_local \
REELIO_PROJECT_ID=proj_local \
REELIO_PLAN_URI=file://$PWD/.render-local/projects/proj_local/jobs/job_local/plan.json \
REELIO_OUTPUT_PREFIX=projects/proj_local/jobs/job_local/output \
node src/index.js
```

## Формат `plan.json`

Ожидается снимок провалидированного `RenderRequest`:

```jsonc
{
  "contractVersion": 1,
  "jobId": "job_01J8…",
  "projectId": "proj_9d1…",
  "plan":   { /* EditPlan, §2 */ },
  "assets": [ /* §3, с objectPath внутри projects/{projectId}/ */ ],
  "export": { /* §4: РЕЗОЛВНУТОЕ разрешение, не maximumAvailable */ }
}
```

Принимается и «плоский» вариант, где `assets` и `export` лежат внутри плана.
Неизвестные поля игнорируются — правило совместимости §0.

`export.resolution` обязано быть конкретным: `maximumAvailable` резолвит только
backend (§1), и worker отвергает его как `RESOLUTION_UNSUPPORTED`. Ширина и
высота берутся из таблицы §1, а не из запроса.

## Решения, о которых стоит знать

**Длительность ролика меньше Σ `clips[].duration`.** Любой плавный переход
требует перекрытия соседних клипов, поэтому итог короче суммы ровно на сумму
перекрытий. Единственный источник истины — `src/timeline.js`; его результат
используют и граф фильтров, и тайминги субтитров, и проверка готового MP4.

**Кадрирование по умолчанию — `cover`.** Кадр масштабируется «в накрытие» и
обрезается по центру: растяжения нет ни в одном режиме. Контрактный вариант §1
(масштаб + поля) доступен как `REELIO_FIT_MODE=contain`.

**Субтитры — ASS, а не `drawtext`.** `drawtext` требует ручного экранирования
текста и не умеет karaoke-подсветку. Если сборка FFmpeg собрана без libass,
вшить субтитры нечем — worker логирует деградацию и всё равно выгружает
`captions.srt` рядом с роликом.

**Текст субтитров берётся из `captions.sampleText`.** Распознавания речи в
контракте нет, поэтому текст раскладывается по клипам — одна реплика на клип.
Если план принесёт `captions.cues` (разрешённое §0 дополнение), берутся они.

**Музыка.** `music.track` — перечисление, а не путь. Настоящие треки
монтируются в `REELIO_MUSIC_DIR` как `{track}.m4a`. Если файла нет,
подложка синтезируется через `aevalsrc` — не ради красоты, а чтобы
музыкальный тракт и ducking оставались рабочими и проверяемыми без бинарных
ассетов в репозитории.

**Ducking** включается только при наличии речи (средняя громкость дорожки выше
−50 dBFS) и `music.track != "none"`. Параметры компрессора зафиксированы §2 и
сверяются с документом тестом `contract-sync`.

**Rotation.** Флаг `-autorotate` намеренно не передаётся: его синтаксис
несовместим между версиями FFmpeg (до 6 требовал значение, с 7 — флаг без
аргумента, и лишний аргумент уезжает в имя выходного файла). Автоповорот
включён по умолчанию, а решения о кадрировании принимаются по уже развёрнутым
размерам из `probe.displayDimensions()`.

**`downloadUrl` worker не заполняет.** Подписывать URL умеет только backend:
у сервисного аккаунта worker'а нет `signBlob` (§9), и это намеренно.

## Тесты

```bash
npm test           # всё
npm run test:unit  # без FFmpeg
npm run test:e2e   # нужен ffmpeg + ffprobe
```

E2E-тесты работают в local mode: хранилище — временный каталог, канал §8.1 —
HTTP-сервер на `127.0.0.1`. Ни облачных ресурсов, ни обращений наружу.

Что проверяется по-настоящему, а не по строкам графа:

* сборка валидного MP4 во всех четырёх разрешениях §1 с проверкой через ffprobe;
* порядок боксов `moov`/`mdat` — то есть реальный `+faststart`;
* ducking — измерением громкости музыки до и во время речи;
* нормализация поворота на видео с display matrix;
* кооперативная отмена: рендер останавливается, `tmp/` убирается, ролик не появляется;
* повреждённый исходник → `SOURCE_UNREADABLE` без утечки путей и вывода ffprobe;
* запуск из дерева образа (`package.json` + `src/`) — гарантия, что COPY полон.

Тест `contract-sync` парсит сам `docs/render-contract.md` и сверяет с ним
таблицы разрешений, фаз прогресса и параметры ducking: worker держит их копию,
и при правке контракта тест краснеет.

## Образ

```bash
docker build -t reelio-worker backend/worker
```

Зависимостей npm нет, поэтому образ — это `ffmpeg + node + src/`: ни `npm ci`,
ни lock-файла, ни multi-stage сборки. Обращения к Cloud Storage сделаны на
`fetch` поверх JSON API, аутентификация — ADC/Workload Identity через
метаданные инстанса. Ключи сервисных аккаунтов не используются и не хранятся.

Минимальная версия FFmpeg — **5.1** (Debian bookworm). Более старые сборки не
знают части режимов `xfade`; worker определяет доступный набор у бинаря и
откатывается на растворение вместо падения.
