# Reelio AI — контракт рендера (v2)

Дополнение к [v1](render-contract.md), а не замена. Всё, что не описано здесь,
берётся из v1 без изменений: разрешения (§1), состояния и фазы (§4),
идемпотентность (§5), пути (§6), формат ошибок (§7), IAM (§9), local mode (§10).

Версия контракта — `render-contract/2`. Обслуживают её **отдельные** деплои:
`reelio-backend-beta` и Cloud Run Job `reelio-ffmpeg-worker-v2`. Production
v1 (`reelio-backend`, `reelio-ffmpeg-worker`) не затрагивается и продолжает
работать со своим контрактом.

| Участник | v1 | v2 |
|---|---|---|
| Backend API | `reelio-backend` | `reelio-backend-beta` |
| FFmpeg worker | `reelio-ffmpeg-worker` | `reelio-ffmpeg-worker-v2` |
| `contractVersion` | `1` | `2` |

---

## 0. Совместимость с v1

Правило то же, что в v1: поле можно **добавить**, но нельзя переименовать или
удалить. v2 добавляет поля и **не удаляет** ни одного поля v1.

**Worker v2 обязан принимать план v1.** `contractVersion: 1` разбирается по
правилам v1 и поднимается до v2 миграцией (§7). План v2 в worker v1 не
отправляется — маршрутизацию по версии делает backend.

Одно поле v1 объявлено **устаревшим**:

| Поле | Статус | Поведение v2 |
|---|---|---|
| `plan.music` | deprecated | Принимается, валидируется, **игнорируется**. В FFmpeg не передаётся. |

Фоновая музыка из продукта убрана целиком: пользователь добавляет трендовый
трек уже внутри Instagram, поверх готового ролика. Поэтому worker v2 никогда
не загружает, не синтезирует и не подмешивает музыку, а `music` в плане
существует только ради старых клиентов.

## 1. Звук

Вместо `music` план несёт один переключатель:

```jsonc
"audio": {
  "keepOriginal": true      // boolean, по умолчанию true
}
```

### `keepOriginal: true`

Оригинальный звук исходников сохраняется. Worker обязан:

1. склеить дорожки клипов в порядке монтажа, **сохранив синхронизацию с видео**:
   каждый клип занимает на аудиотаймлайне ровно тот же отрезок, что и на
   видеотаймлайне (§3);
2. убрать щелчки на стыках — микрофейд по 15 мс с обеих сторон реза, а на
   плавных переходах `acrossfade` длиной самого перехода;
3. нормализовать громкость (`loudnorm`, цель −16 LUFS, TP −1.5 dBTP) — но
   только если в материале действительно есть звук выше порога тишины;
4. защитить мастер от клиппинга лимитером.

**Клипы без звука** (фото и видео с немой дорожкой) занимают свой отрезок
таймлайна тишиной. Это не «искусственная звуковая дорожка», а выравнивание:
без него звук последующих клипов уехал бы вперёд относительно картинки.
Никакого синтезированного содержимого — ни музыки, ни атмосферы — не
добавляется.

**Если звука нет нигде** (весь ролик из фото или из немых видео) — аудиопоток
в MP4 не создаётся вовсе: ролик экспортируется без звука, как при
`keepOriginal: false`.

### `keepOriginal: false`

Ролик экспортируется **без аудиопотока**. В MP4 нет дорожки AAC, `ffprobe`
не показывает ни одного `codec_type: audio`.

### Субтитры и звук

Автоматические субтитры строятся по распознанной речи и от этого
переключателя **не зависят**: текст уже извлечён на этапе анализа и живёт в
плане. Ролик без звука может нести субтитры.

## 2. Переходы

v1 знал четыре значения. v2 вводит **каталог**: `transition` становится
объектом, а множество типов расширяется до того, что реально умеет `xfade`.

```jsonc
"transition": {
  "type": "dissolve",        // §2.1
  "durationSeconds": 0.45,   // 0.15 .. 1.5
  "intensity": "balanced"    // calm | balanced | dynamic
}
```

Строка вместо объекта тоже принимается — это форма v1: `"crossfade"`
эквивалентно `{ "type": "crossfade", "durationSeconds": null, "intensity": "balanced" }`.

### 2.1 Каталог

| `type` | Фильтр FFmpeg | Группа |
|---|---|---|
| `cut` | — (стык без перекрытия) | базовые |
| `dissolve` | `xfade=fade` | базовые |
| `crossfade` | `xfade=fade` (синоним `dissolve`, форма v1) | базовые |
| `fadeBlack` | `xfade=fadeblack` | затемнения |
| `fadeWhite` | `xfade=fadewhite` | затемнения |
| `wipeLeft` | `xfade=wipeleft` | шторки |
| `wipeRight` | `xfade=wiperight` | шторки |
| `wipeUp` | `xfade=wipeup` | шторки |
| `wipeDown` | `xfade=wipedown` | шторки |
| `slideLeft` | `xfade=slideleft` | сдвиги |
| `slideRight` | `xfade=slideright` | сдвиги |
| `slideUp` | `xfade=slideup` | сдвиги |
| `slideDown` | `xfade=slidedown` | сдвиги |
| `smoothLeft` | `xfade=smoothleft` | плавные |
| `smoothRight` | `xfade=smoothright` | плавные |
| `smoothUp` | `xfade=smoothup` | плавные |
| `smoothDown` | `xfade=smoothdown` | плавные |
| `circleOpen` | `xfade=circleopen` | круг |
| `circleClose` | `xfade=circleclose` | круг |
| `zoomIn` | `xfade=zoomin` | масштаб |
| `pixelize` | `xfade=pixelize` | эффекты |
| `radial` | `xfade=radial` | эффекты |
| `blur` | `xfade=hblur` | эффекты |

Сторонние transition pack'и не используются: только то, что есть в самой
сборке FFmpeg, с понятной лицензией.

### 2.2 Определение доступности

Worker при запуске спрашивает у своего бинаря `ffmpeg -h filter=xfade` и
строит **проверенный каталог** — пересечение таблицы §2.1 с тем, что сборка
действительно умеет. Каталог отдаётся backend'у и клиенту, чтобы UI не
показывал переход, который не отрендерится.

Если план просит тип вне проверенного каталога, worker откатывается на
`dissolve` и записывает это в `notes`, а не падает.

### 2.3 Длительность и интенсивность

`durationSeconds` — 0.15 .. 1.5. Если не задана, берётся из `intensity`:

| `intensity` | Длительность по умолчанию | Смысл |
|---|---|---|
| `calm` | 0.8 с | Длинные мягкие переходы |
| `balanced` | 0.45 с | Значение по умолчанию |
| `dynamic` | 0.25 с | Короткие резкие переходы |

Жёсткое ограничение сохраняется: перекрытие не длиннее 40% более короткого из
соседних клипов. Если после ограничения остаётся меньше 0.15 с, переход
вырождается в `cut`.

### 2.4 Превью

Backend отдаёт короткий MP4-превью на каждый тип каталога. Превью
генерируются worker'ом из двух синтетических клипов (`testsrc2`) один раз и
кэшируются в бакете: `previews/transitions/{type}.mp4`.

## 3. Таймлайн

Как в v1: `cut` стыкует клипы встык, плавный переход перекрывает соседей, и
итоговая длительность меньше Σ `clips[].duration` на сумму перекрытий.

Аудиотаймлайн **обязан повторять видеотаймлайн** сегмент в сегмент. Это
единственный способ сохранить синхронизацию при перекрытиях.

## 4. `TextOverlay`

Новый массив `plan.textOverlays` (до 20 элементов).

```jsonc
{
  "id": "text_1",                  // уникален в плане
  "text": "Наша поездка",          // ≤ 200 символов, UTF-8
  "startSeconds": 3.0,             // либо привязка к клипу, см. ниже
  "endSeconds": 6.0,
  "clipId": null,                  // если задан — время отсчитывается от клипа
  "position": {
    "anchor": "top",               // top | center | bottom
    "x": 0.5,                      // 0..1 от ширины кадра, центр текста
    "y": 0.18                      // 0..1 от высоты кадра, центр текста
  },
  "fontId": "montserrat",          // §5
  "fontWeight": "bold",            // regular | medium | bold
  "fontSizeRatio": 0.055,          // доля ВЫСОТЫ кадра: 0.02 .. 0.15
  "colorHex": "#FFFFFF",
  "align": "center",               // left | center | right
  "opacity": 1.0,                  // 0..1
  "background": {                  // плашка; null — без неё
    "colorHex": "#000000",
    "opacity": 0.45,
    "paddingRatio": 0.02,
    "radiusRatio": 0.01
  },
  "outline": {                     // обводка; null — без неё
    "colorHex": "#000000",
    "widthRatio": 0.004
  },
  "shadow": {                      // тень; null — без неё
    "colorHex": "#000000",
    "opacity": 0.6,
    "offsetRatio": 0.004
  },
  "animation": "fade"              // none | fade | slide | pop
}
```

### 4.1 Нормализованные координаты

`x`, `y`, `fontSizeRatio` и все `*Ratio` — **доли кадра**, а не пиксели.
Поэтому один и тот же план даёт визуально одинаковую раскладку в 720p, 1080p,
2K и 4K: worker умножает доли на реальный размер кадра.

Единица отсчёта для вертикальных величин (кегль, отступы, обводка, тень) —
**высота** кадра; для горизонтальных (`x`) — ширина. `y` тоже доля высоты.

### 4.2 Безопасная зона Instagram Reels

Элементы интерфейса Reels перекрывают края кадра. Безопасная зона в долях:

| Сторона | Доля |
|---|---|
| сверху | 0.14 |
| снизу | 0.20 |
| слева | 0.06 |
| справа | 0.06 |

Backend и UI показывают сетку и **предупреждают**, если центр текста выходит
за зону. Worker сдвигает текст внутрь зоны и записывает это в `notes`:
испорченный экспорт хуже, чем сдвинутая на пару процентов подпись.

`anchor` задаёт значение `y` по умолчанию: `top` → 0.18, `center` → 0.5,
`bottom` → 0.80. Явный `y` перекрывает якорь.

### 4.3 Безопасность текста

Пользовательский текст **никогда** не попадает в строку `filter_complex`.
Worker пишет его в UTF-8 файл `.ass` и передаёт FFmpeg только путь к файлу.
Это снимает целый класс инъекций через `:`, `'`, `,`, `\` и `[]` в тексте.

### 4.4 Анимации

| `animation` | Реализация |
|---|---|
| `none` | Появление и исчезновение мгновенные |
| `fade` | `\fad(250,250)` |
| `slide` | `\move` снизу вверх на 4% высоты за 300 мс |
| `pop` | `\t` масштаб 60% → 100% за 220 мс |

## 5. Шрифты

Каталог из проверенных open-source шрифтов Google Fonts с кириллицей. Файлы
и лицензии лежат в репозитории (`assets/fonts/`), один и тот же файл
используется и web-превью, и FFmpeg, поэтому экспорт совпадает с экраном.

| `fontId` | Семейство | Группа | Лицензия |
|---|---|---|---|
| `inter` | Inter | современные | OFL 1.1 |
| `montserrat` | Montserrat | современные | OFL 1.1 |
| `manrope` | Manrope | современные | OFL 1.1 |
| `roboto` | Roboto | строгие | OFL 1.1 |
| `pt_sans` | PT Sans | строгие | OFL 1.1 |
| `oswald` | Oswald | эмоциональные | OFL 1.1 |
| `unbounded` | Unbounded | эмоциональные | OFL 1.1 |
| `caveat` | Caveat | декоративные | OFL 1.1 |
| `pacifico` | Pacifico | декоративные | OFL 1.1 |

Неизвестный `fontId` не ошибка: worker берёт `inter` и пишет `notes`.

## 6. Субтитры

`plan.captions` расширяется:

```jsonc
"captions": {
  "enabled": true,
  "language": "ru",
  "style": "bold",              // clean | bold | karaoke | minimal
  "colorHex": "#FFFFFF",
  "highlightColorHex": "#A855F7", // цвет выделения ключевых слов / karaoke
  "fontId": "montserrat",
  "position": "bottom",         // top | center | bottom
  "maxLineChars": 26,
  "cues": [                     // распознанная речь; §6.1
    {
      "start": 1.20,
      "end": 3.05,
      "text": "Мы приехали на море",
      "words": [                // опционально — для karaoke и выделения
        { "start": 1.20, "end": 1.55, "text": "Мы", "highlight": false },
        { "start": 1.55, "end": 2.10, "text": "приехали", "highlight": true }
      ]
    }
  ]
}
```

`sampleText` из v1 сохраняется и используется, только когда `cues` пуст.

### 6.1 Источник `cues`

Реплики приходят из анализа материалов (распознавание речи с таймкодами) и
кладутся в план backend'ом. Worker **не распознаёт речь сам** — он получает
готовый текст. Это держит образ worker'а лёгким и делает рендер
детерминированным.

## 7. Миграция v1 → v2

Выполняется на входе worker'а v2 и на backend'е; результат — план v2.

| v1 | v2 |
|---|---|
| `contractVersion: 1` | `contractVersion: 2` |
| `music: { track, volume }` | отбрасывается; `audio.keepOriginal = true` |
| `transition: "crossfade"` | `{ type: "crossfade", durationSeconds: null, intensity: "balanced" }` |
| `transition: "fade"` | `{ type: "fadeBlack", … }` |
| `transition: "slide"` | `{ type: "slideLeft", … }` |
| `transition: "cut"` | `{ type: "cut", … }` |
| `captions.sampleText` | сохраняется; `cues` пуст |
| нет `textOverlays` | `[]` |

Обратной миграции нет: план v2 в worker v1 не отправляется.

## 8. Экспорт «Instagram Reels»

Пресет `instagramReels` фиксирует параметры, которые Instagram обрабатывает
без перекодирования потерь:

```
resolution : fullHd1080 (1080 × 1920)
fps        : 30
video      : h264 high, yuv420p, 8 / 10 Мбит/с, GOP 60
audio      : aac 48 кГц stereo 160 kbps — либо дорожки нет вовсе (§1)
container  : mp4 +faststart
обложка    : projects/…/output/thumbnail.jpg, кадр из coverClipId
безопасные зоны : §4.2, проверяются для каждого TextOverlay
длительность    : до 120 с (потолок продукта не меняется)
```

Пресет — это значение `export.preset`; конкретные `resolution`/`fps` он
перекрывает. Остальные разрешения §1 остаются доступны как и раньше.

## 9. Стоимость анализа

Анализ материалов (§ дополнение к v1) тратит платные вызовы Gemini, поэтому у
него **отдельные лимиты**, не связанные с лимитами `/edit-plan`:

| Лимит | Значение по умолчанию |
|---|---|
| Кадров на видео | 12 |
| Секунд аудио на видео | 120 |
| Анализов в сутки на пользователя | 20 |
| Анализов в сутки на проект | 8 |

`MediaAnalysis` сохраняется отдельно от плана
(`projects/…/analysis/{assetId}.json`) и переиспользуется: повторно исходник
в Gemini не отправляется, пока не изменился его `checksumCrc32c`.
